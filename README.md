# Aska

iOS-приложение на SwiftUI для отслеживания менструального цикла: отмечает начало и конец
периода, хранит историю и синхронизирует её между устройствами через iCloud.

## Структура репозитория

```
Aska/                 код приложения
  AskaApp.swift       точка входа, выбор экрана (загрузка / онбординг / главный)
  CycleEvent.swift    модель события (SwiftData), сборка периодов из событий, подсчёт дней
  CycleStore.swift    API: старт, стоп, отмена, удаление старта и стопа, периоды за месяц
  CalendarPeriods.swift  периоды месяца: факт и прогноз
  CycleSummary.swift  данные для главного экрана
  UserSettings.swift  настройки пользователя и их валидация
  SettingsStore.swift хранение настроек (локально + iCloud)
  Theme.swift         дизайн-токены (OKLCH → sRGB), светлая/тёмная тема
  Components.swift    иконки, таб-бар, степпер, переключатель, карточки
  CycleRing.swift     светящееся кольцо цикла

  DemoMode.swift      демо-данные для скриншотов (только Debug)

  CycleStoreTests.swift  корнер-кейсы сборки периодов, API и подсчёта дней
  SettingsTests.swift    валидация настроек и их синхронизация
```

Файл `Aska.xcodeproj` в репозитории не хранится — он генерируется командой `xcodegen generate`
из `project.yml`.

## Как это работает

### История: храним события, а не периоды

В базе лежат только **события** (`CycleEvent`): «период начался» или «период закончился»
с датой и временем ввода (`createdAt`). Пар «начало–окончание» в базе нет — периоды
собираются из событий при каждой отрисовке (`Period.derive`):

1. события сортируются по дате (при равенстве старт идёт раньше стопа);
2. несколько стартов подряд дают один период с **самого раннего** из них;
3. несколько стопов подряд закрывают его **самым поздним** из них;
4. стоп без старта перед ним игнорируется.

То есть если введены и короткий, и длинный вариант, длинный перекрывает короткий.
Ничего не удаляется и не переписывается, поэтому если лишнее событие удалить,
короткий период снова появится. Пример:

| События | На экране |
|---|---|
| старт 1 сент, стоп 4 сент | 1–4 сент |
| + стоп 7 сент | 1–7 сент (длинный перекрыл короткий) |
| удалили стоп 7 сент | снова 1–4 сент |

API (`CycleStore`):

- **`startCycle(at:)`** — добавляет событие «начало» с переданной датой. Разрешено и при
  идущем периоде: более ранний старт удлиняет период.
- **`stopCycle(at:)`** — добавляет событие «окончание». Нужен хотя бы один старт не позже этой даты.
  Второй, более поздний стоп удлиняет период; более ранний — ни на что не влияет, пока есть поздний.
- **`undoLast()`** — удаляет **последнее введённое** изменение (по `createdAt`, а не по дате):
  одно событие от кнопок старт/стоп или все события, добавленные одной правкой в календаре.
  После стопа период снова идёт, после старта старт исчезает. Возвращает тип удалённого события.
- **`deleteStop(onDay:)`** — удаляет все отметки окончания в выбранный календарный день.
  Если лишний длинный стоп удалён — снова показывается короткий период. Если стопа в этот
  день нет — ошибка. Удаление стопа между двумя периодами склеивает их в один.
- **`deleteStart(onDay:)`** — удаляет все отметки начала в выбранный день. Если лишний ранний
  старт удалён — снова показывается короткий период. Стопы, оставшиеся без старта перед ними,
  не удаляются, но при сборке периодов игнорируются. Удаление старта второго периода
  присоединяет его стоп к первому (длинный перекрывает короткий).
- **`periods(inMonthOf:settings:)`** — периоды, пересекающиеся с календарным месяцем, где лежит
  переданная дата. Каждый период — `CalendarPeriod` с датами-днями (окончание включительно)
  и пометками `startCertainty` / `endCertainty`: `.fact` или `.forecast`. Подробнее — ниже.
- **`summary(settings:)`** — данные для главного экрана (`CycleSummary`), см. ниже.
- **`markDay(_:)`** — календарный «+»: отмечает один день. День сразу после периода продлевает
  его, сразу перед — переносит начало, между двумя периодами — склеивает их, иначе создаёт
  период в один день. Будущие дни — ошибка, уже отмеченные — без изменений.
- **`unmarkDay(_:)`** — календарный «×»: убирает один день. Первый/последний день сдвигает
  начало/окончание, день в середине делит период на два, единственный день удаляет период.
- **`CycleStore.eventDate(for:onDay:now:)`** — превращает выбранный на экране день в момент события:
  сегодня — текущее время; прошлый день — 00:00 для старта и 23:59:59 для стопа,
  чтобы весь день попал в период.

Валидация (нарушение → `CycleError`, данные не меняются):

- даты в будущем запрещены (граница «ровно сейчас» разрешена);
- стоп без предшествующего старта запрещён (стоп в момент старта разрешён);
- отмена на пустой истории и удаление несуществующего старта или стопа — ошибка.

### Экраны (по дизайн-пакету `design_handoff_cycle_tracker`)

- **Сегодня** — кольцо цикла: прошедшие дни закрашены акцентом по часовой стрелке, поверх —
  сегмент менструации с насечками, в центре «день/длина цикла». Слева от главной кнопки —
  отмена (приглушена, когда отменять нечего). Главная кнопка: капля — «начались»
  (долгое нажатие 0,45 с открывает «-1 Вчера» / «-2 Позавчера»), квадрат — «закончились».
  Свайп вправо — календарь.
- **Календарь** — сетка месяца с понедельника; факт — заливка, прогноз — пунктир, сегодня —
  кольцо. Тап по прошедшей дате — кнопка «+» (`markDay`) или «×» (`unmarkDay`) прямо на ней.
  Свайп влево/вправо и стрелки — месяцы.
- **Профиль** — дата рождения, год начала менструаций, длительности цикла и менструации,
  напоминания. Изменения сохраняются сразу.
- Светлая и тёмная тема — по системной; в тёмной кольцо переливается. Палитра — «warm».

### Периоды за месяц: факт и прогноз

`periods(inMonthOf:settings:)` → `[CalendarPeriod]` (логика в `CalendarPeriods.forMonth`):

| Период | Начало | Окончание |
|---|---|---|
| Зафиксированный (есть старт и стоп) | факт | факт |
| Идущий сейчас | факт | прогноз: начало + длина периода − 1, но не раньше сегодня |
| Будущий | прогноз | прогноз |

Прогноз считается стандартно, как в приложениях-календарях. Длина цикла — это число дней
от начала одного периода до начала следующего, поэтому прогноз строится от **начала
последнего** периода (зафиксированного или идущего):

- начало = начало последнего периода + длина цикла;
- период длится «длину периода» дней, включая первый день: окончание = начало + длина периода − 1;
- следующие прогнозы — через каждую длину цикла от предыдущего прогнозного начала,
  поэтому можно запрашивать любой будущий месяц.

Пример (цикл 28, период 5, последний период начался 1 авг): прогнозы 29 авг – 2 сент,
26–30 сент, 24–28 окт, 21–25 нояб.

В ответ попадают периоды, которые хотя бы одним днём пересекаются с месяцем, так что
период на стыке месяцев вернётся в обоих. «Следующий период ≈» на главном экране берётся
из того же прогноза (`CalendarPeriods.nextForecast`).

### Главный экран: день цикла и проценты

`summary(settings:)` → `CycleSummary`:

| Поле | Что это | Пример |
|---|---|---|
| `cycleLength` | длина цикла из настроек, дней | 28 |
| `periodLength` | длина периода из настроек, дней | 4 |
| `dayOfCycle` | какой сегодня день цикла; день начала последнего периода — день 1 | 14 |
| `periodPercent` | сколько процентов цикла занимает период: период / цикл × 100 | 14.29 |
| `todayPercent` | сколько процентов цикла прошло, включая сегодня: день / цикл × 100 | 50 |
| `isLate` | день цикла больше длины цикла (задержка) | false |

- Если периодов ещё нет, `dayOfCycle` и `todayPercent` — `nil`.
- При задержке `dayOfCycle` продолжает расти (29, 30, …), а `todayPercent` остаётся 100.
- Проценты — дробные числа от 0 до 100, округлять для показа нужно на экране.

### Настройки

Спрашиваются при первом запуске, меняются на экране «Профиль». Допустимые значения:

| Поле | Диапазон |
|---|---|
| Дата рождения | возраст от 8 до 80 лет |
| Год начала менструаций | через 8–18 лет после года рождения, не позже текущего года |
| Длительность цикла | 15–45 дней |
| Длительность менструации | 1–12 дней |
| Напоминания | вкл/выкл: уведомление в 9:00 накануне прогнозного начала |

### Хранение и перенос на новое устройство

- **История** — SwiftData с синхронизацией в приватную базу CloudKit пользователя.
  Данные лежат в iCloud пользователя; разработчик к ним доступа не имеет.
- **Настройки** — iCloud Key-Value Store + локальная копия в UserDefaults.
  При расхождении побеждает версия из iCloud.
- На новом устройстве достаточно войти в тот же Apple ID и установить приложение.
  Если локальных настроек нет, приложение ~2 секунды ждёт их из iCloud и только потом
  показывает онбординг.

## Ограничения

- **iCloud-синхронизация работает только в подписанной сборке** с включённой возможностью
  iCloud (нужен платный Apple Developer и контейнер `iCloud.com.sksakura.aska`).
  Сборка из CI сейчас неподписанная — в ней данные хранятся только на устройстве.
- **Офлайн-работа на двух устройствах** конфликтов не создаёт: события с обоих устройств
  просто объединяются, и более длинный период перекрывает более короткий.
- **Удаление работает по дню**: удаляются все отметки нужного типа в этот день.
- **Старт внутри уже закрытого периода не создаёт новый период** — он поглощается
  (считается «коротким вариантом» того же периода).
- **Настройки: «последняя запись побеждает»** — одновременные правки на двух устройствах
  не объединяются, сохранится одна из них.
- **Ожидание iCloud при первом запуске — 2 секунды.** При медленной сети настройки могут
  прийти позже; тогда онбординг сменится главным экраном автоматически, как только они придут.
- **Точность ввода — день.** При выборе прошлого дня старт ставится на 00:00, стоп — на 23:59:59.
- **Прогноз простой**: от начала последнего периода по длинам из настроек;
  фактическая история (средняя длина циклов) не используется.
- **Просроченный прогноз не сдвигается**: если прогнозная дата начала прошла, а старт
  не отмечен, прогноз остаётся в прошлом, пока пользователь не отметит старт.
- **Прогнозы назад не строятся**: в месяцах до последнего периода показываются только факты.
- **Правки в календаре меняют события**, а не хранят отдельные «переопределения» дат;
  «×» удаляет отметки на этот день, и отмена (undo) их не вернёт — вернуть день можно «+».
- **Выход из календаря** — через таб-бар внизу (в макете этого не было).
- **Кнопка «закончились»** ставит окончание на текущий момент; длительность менструации
  в настройках при этом не меняется (в макете меняется), реальная длина видна на кольце.
- Только iPhone, портретная ориентация, iOS 17+.
- Интерфейс только на русском.

## Тесты

Тестовый таргет `AskaTests` (Swift Testing) покрывает корнер-кейсы, подобранные
по граничным значениям, переходам состояний и угадыванию ошибок:

| Группа | Кейсы |
|---|---|
| Сборка периодов | PR1–PR10: пусто, только старт, старт+стоп, два периода, два старта подряд, два стопа подряд, вложенные, стоп без старта, одинаковый момент, несортированный ввод |
| `startCycle` | S1–S5: дата сохраняется, граница «ровно сейчас» / будущее, старт при идущем периоде удлиняет, старт внутри закрытого, новый период |
| `stopCycle` | P1–P7: обычный стоп, стоп в момент старта, на 1 с раньше старта, пусто, будущее, поздний стоп удлиняет, ранний не укорачивает |
| `undoLast` | U1–U5: пусто, отмена старта, отмена стопа, отмена по порядку ввода, а не по дате, откат до пустой истории |
| `deleteStop` | DS1–DS7: удаление длинного стопа возвращает короткий период, удаление единственного, нет стопа в день, старт в тот же день не трогается, любое время внутри дня, несколько стопов в день, стоп между периодами |
| `deleteStart` | DSt1–DSt6: удаление раннего старта возвращает короткий период, удаление единственного, нет старта в день, стоп в тот же день не трогается, несколько стартов в день, старт второго периода |
| Периоды за месяц | FC1–FC16: пусто, факт, прогноз от начала последнего, цепочка прогнозов, фактическая длина не сдвигает прогноз, идущий период (факт/прогноз), идущий дольше обычного, прогноз после идущего, стык месяцев, границы месяца, прогноз только от последнего периода, прошлый месяц, ближайший прогноз, длины из настроек, API стора, период в 1 день |
| Главный экран | CS1–CS9: нет истории, середина цикла (50%), день начала = 1, последний день = 100%, задержка, от начала последнего периода, переход через полночь, длины из настроек, API стора |
| Выбор дня | M1–M4: сегодня → текущее время, прошлый день → 00:00 / 23:59:59, старт и стоп в один день, завтра → отказ |
| Дни | D1–D2: переход через полночь, переход на летнее время |
| Правка дней в календаре | MK1–MK8, UM1–UM9: «+» на отдельный день, после/перед периодом, в промежутке (склейка), уже отмеченный, будущий, сегодня; «×» в середине (разделение), первый/последний/единственный день, сегодня в идущем, середина идущего, неотмеченный, «короткий вариант», «×» затем «+», отмена правки целиком |
| Отметки дней | DM1–DM3: факт, идущий период (факт до сегодня, дальше прогноз), прогноз и приоритет факта |
| Тема и напоминания | TH1–TH3, RM1–RM3: перевод OKLCH → sRGB, обрезка вне охвата, градиент кольца; время напоминания, прошедшее время, ближайший прогноз |
| Валидация настроек | V1–V6: типичные значения, границы длительностей, год начала менструаций, год рождения, не в будущем, диапазон для степпера |
| Хранение настроек | K1–K8: первый запуск, запись в оба хранилища, восстановление из iCloud, без iCloud, конфликт, внешнее изменение, повреждённые данные |

Запуск на Mac:

```sh
xcodegen generate
xcodebuild test -project Aska.xcodeproj -scheme Aska -destination 'platform=iOS Simulator,name=iPhone 16'
```

или в Xcode: Cmd+U.

## CI

`.github/workflows/ios-build.yml` запускается на каждый push и pull request:

1. **Tests** — генерирует проект и прогоняет `AskaTests` на симуляторе iPhone.
   При падении результаты (`TestResults.xcresult`) прикладываются к запуску.
2. **Build IPA** — запускается **только если тесты прошли** (`needs: test`).
   Собирает неподписанный `Aska-unsigned.ipa` и выкладывает его в артефакты запуска.
3. **Screenshots** — тоже после тестов: запускает приложение на симуляторе iPhone с демо-данными
   и снимает все экраны в светлой и тёмной теме (артефакт `Screenshots`):
   `onboarding`, `today` (14-й день цикла), `today-active` (идёт 3-й день), `calendar`, `profile`.
   При push картинки также публикуются в ветку `screenshots` — их удобно смотреть прямо на GitHub.

Демо-режим есть только в Debug-сборке: запуск с аргументом `-demo <сценарий>`
(`Aska/DemoMode.swift`). Данные в нём — в памяти, настоящие данные и настройки не трогаются,
напоминания не планируются.

## Установка на телефон

Неподписанный `.ipa` на iPhone напрямую не ставится. Варианты:

- **С Mac:** `brew install xcodegen && xcodegen generate && open Aska.xcodeproj`, в
  Signing & Capabilities выбрать свою Team, подключить iPhone, включить на нём
  «Режим разработчика» и нажать ▶︎.
- **Без компьютера:** платный Apple Developer + подписанная сборка в CI с выгрузкой
  в TestFlight (ещё не настроено).

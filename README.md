# Aska

iOS-приложение на SwiftUI для отслеживания менструального цикла: отмечает начало и конец
периода, хранит историю и синхронизирует её между устройствами через iCloud.

## Структура репозитория

```
Aska/                 код приложения
  AskaApp.swift       точка входа, выбор экрана (загрузка / онбординг / главный)
  CycleEvent.swift    модель события (SwiftData), сборка периодов из событий, подсчёт дней
  CycleStore.swift    API: старт, стоп, отмена, удаление старта и стопа
  UserSettings.swift  настройки пользователя и их валидация
  SettingsStore.swift хранение настроек (локально + iCloud)
  MainView.swift      главный экран и история
  SettingsViews.swift онбординг и экран настроек
AskaTests/            тестовый таргет (Swift Testing)
  CycleStoreTests.swift  корнер-кейсы сборки периодов, API и подсчёта дней
  SettingsTests.swift    валидация настроек и их синхронизация
Support/              Info.plist (доп. ключи) и entitlements (iCloud)
project.yml           описание проекта для XcodeGen
.github/workflows/    CI: тесты → сборка
```

Файл `Aska.xcodeproj` в репозитории не хранится — он генерируется командой `xcodegen generate`
из `project.yml`.

## Как это работает

### История: храним события, а не периоды

В базе лежат только **события** (`CycleEvent`): «период начался» или «период закончился»
с датой и временем ввода (`createdAt`). Пар «начало–окончание» в базе нет — периоды
собираются из событий при каждой отрисовке (`Period.derive`):

1. события сортируются по дате (при равенстве старт идёт раньше стопа);
2. несколько стартов подряд дают один период с **самого раннего** из них;
3. несколько стопов подряд закрывают его **самым поздним** из них;
4. стоп без старта перед ним игнорируется.

То есть если введены и короткий, и длинный вариант, длинный перекрывает короткий.
Ничего не удаляется и не переписывается, поэтому если лишнее событие удалить,
короткий период снова появится. Пример:

| События | На экране |
|---|---|
| старт 1 сент, стоп 4 сент | 1–4 сент |
| + стоп 7 сент | 1–7 сент (длинный перекрыл короткий) |
| удалили стоп 7 сент | снова 1–4 сент |

API (`CycleStore`):

- **`startCycle(at:)`** — добавляет событие «начало» с переданной датой. Разрешено и при
  идущем периоде: более ранний старт удлиняет период.
- **`stopCycle(at:)`** — добавляет событие «окончание». Нужен хотя бы один старт не позже этой даты.
  Второй, более поздний стоп удлиняет период; более ранний — ни на что не влияет, пока есть поздний.
- **`undoLast()`** — удаляет **последнее введённое** событие (по `createdAt`, а не по дате).
  После стопа период снова идёт, после старта старт исчезает. Возвращает тип удалённого события.
- **`deleteStop(onDay:)`** — удаляет все отметки окончания в выбранный календарный день.
  Если лишний длинный стоп удалён — снова показывается короткий период. Если стопа в этот
  день нет — ошибка. Удаление стопа между двумя периодами склеивает их в один.
- **`deleteStart(onDay:)`** — удаляет все отметки начала в выбранный день. Если лишний ранний
  старт удалён — снова показывается короткий период. Стопы, оставшиеся без старта перед ними,
  не удаляются, но при сборке периодов игнорируются. Удаление старта второго периода
  присоединяет его стоп к первому (длинный перекрывает короткий).
- **`CycleStore.eventDate(for:onDay:now:)`** — превращает выбранный на экране день в момент события:
  сегодня — текущее время; прошлый день — 00:00 для старта и 23:59:59 для стопа,
  чтобы весь день попал в период.

Валидация (нарушение → `CycleError`, данные не меняются):

- даты в будущем запрещены (граница «ровно сейчас» разрешена);
- стоп без предшествующего старта запрещён (стоп в момент старта разрешён);
- отмена на пустой истории и удаление несуществующего старта или стопа — ошибка.

На экране:

- «Период начался» / «Период закончился» → «Сегодня / Вчера / Позавчера / Выбрать дату…».
  Для окончания дни раньше начала текущего периода не предлагаются.
- «Отменить начало/окончание <дата>» — отмена последнего введённого события.
- В истории период можно смахнуть влево → «Удалить начало» (`deleteStart(onDay:)`) или
  «Удалить окончание» (`deleteStop(onDay:)`).

### Настройки

Год рождения, возраст первой менструации, длина цикла и длина периода. Спрашиваются при
первом запуске, меняются через ⚙︎ на главном экране. Допустимые значения:

| Поле | Диапазон |
|---|---|
| Год рождения | от «текущий − 80» до «текущий − 8» |
| Возраст первой менструации | 8–18 лет, и год рождения + возраст ≤ текущий год |
| Длина цикла | 20–45 дней |
| Длина периода | 1–10 дней |

### Хранение и перенос на новое устройство

- **История** — SwiftData с синхронизацией в приватную базу CloudKit пользователя.
  Данные лежат в iCloud пользователя; разработчик к ним доступа не имеет.
- **Настройки** — iCloud Key-Value Store + локальная копия в UserDefaults.
  При расхождении побеждает версия из iCloud.
- На новом устройстве достаточно войти в тот же Apple ID и установить приложение.
  Если локальных настроек нет, приложение ~2 секунды ждёт их из iCloud и только потом
  показывает онбординг.

## Ограничения

- **iCloud-синхронизация работает только в подписанной сборке** с включённой возможностью
  iCloud (нужен платный Apple Developer и контейнер `iCloud.com.sksakura.aska`).
  Сборка из CI сейчас неподписанная — в ней данные хранятся только на устройстве.
- **Офлайн-работа на двух устройствах** конфликтов не создаёт: события с обоих устройств
  просто объединяются, и более длинный период перекрывает более короткий.
- **Удаление работает по дню**: удаляются все отметки нужного типа в этот день.
- **Старт внутри уже закрытого периода не создаёт новый период** — он поглощается
  (считается «коротким вариантом» того же периода).
- **Настройки: «последняя запись побеждает»** — одновременные правки на двух устройствах
  не объединяются, сохранится одна из них.
- **Ожидание iCloud при первом запуске — 2 секунды.** При медленной сети настройки могут
  прийти позже; тогда онбординг сменится главным экраном автоматически, как только они придут.
- **Точность ввода — день.** При выборе прошлого дня старт ставится на 00:00, стоп — на 23:59:59.
- **Прогноз следующего периода простой**: дата начала последнего периода + длина цикла из
  настроек. Фактическая история для прогноза не используется.
- Только iPhone, портретная ориентация, iOS 17+.
- Интерфейс только на русском.

## Тесты

Тестовый таргет `AskaTests` (Swift Testing) покрывает корнер-кейсы, подобранные
по граничным значениям, переходам состояний и угадыванию ошибок:

| Группа | Кейсы |
|---|---|
| Сборка периодов | PR1–PR10: пусто, только старт, старт+стоп, два периода, два старта подряд, два стопа подряд, вложенные, стоп без старта, одинаковый момент, несортированный ввод |
| `startCycle` | S1–S5: дата сохраняется, граница «ровно сейчас» / будущее, старт при идущем периоде удлиняет, старт внутри закрытого, новый период |
| `stopCycle` | P1–P7: обычный стоп, стоп в момент старта, на 1 с раньше старта, пусто, будущее, поздний стоп удлиняет, ранний не укорачивает |
| `undoLast` | U1–U5: пусто, отмена старта, отмена стопа, отмена по порядку ввода, а не по дате, откат до пустой истории |
| `deleteStop` | DS1–DS7: удаление длинного стопа возвращает короткий период, удаление единственного, нет стопа в день, старт в тот же день не трогается, любое время внутри дня, несколько стопов в день, стоп между периодами |
| `deleteStart` | DSt1–DSt6: удаление раннего старта возвращает короткий период, удаление единственного, нет старта в день, стоп в тот же день не трогается, несколько стартов в день, старт второго периода |
| Выбор дня | M1–M4: сегодня → текущее время, прошлый день → 00:00 / 23:59:59, старт и стоп в один день, завтра → отказ |
| Дни | D1–D2: переход через полночь, переход на летнее время |
| Валидация настроек | V1–V4: типичные значения, границы всех диапазонов, возраст первой менструации в будущем |
| Хранение настроек | K1–K8: первый запуск, запись в оба хранилища, восстановление из iCloud, без iCloud, конфликт, внешнее изменение, повреждённые данные |

Запуск на Mac:

```sh
xcodegen generate
xcodebuild test -project Aska.xcodeproj -scheme Aska -destination 'platform=iOS Simulator,name=iPhone 16'
```

или в Xcode: Cmd+U.

## CI

`.github/workflows/ios-build.yml` запускается на каждый push и pull request:

1. **Tests** — генерирует проект и прогоняет `AskaTests` на симуляторе iPhone.
   При падении результаты (`TestResults.xcresult`) прикладываются к запуску.
2. **Build IPA** — запускается **только если тесты прошли** (`needs: test`).
   Собирает неподписанный `Aska-unsigned.ipa` и выкладывает его в артефакты запуска.

## Установка на телефон

Неподписанный `.ipa` на iPhone напрямую не ставится. Варианты:

- **С Mac:** `brew install xcodegen && xcodegen generate && open Aska.xcodeproj`, в
  Signing & Capabilities выбрать свою Team, подключить iPhone, включить на нём
  «Режим разработчика» и нажать ▶︎.
- **Без компьютера:** платный Apple Developer + подписанная сборка в CI с выгрузкой
  в TestFlight (ещё не настроено).
